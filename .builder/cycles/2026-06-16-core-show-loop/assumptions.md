# Core Show Loop Assumptions

What must be true:

- A single saved show is enough context for a useful first-session loop.
- Users tolerate AI generation when it is explicit, editable, and locally saved.
- Basic local preparation and fragments should remain free because they build trust before Pro.
- Pro feels fair when it unlocks repeated generation and more saved shows rather than private notes.

Falsifiers:

- Users do not return to saved generated plans.
- Users feel blocked too early by Pro before understanding the value.
- Preview links feel unsafe, irrelevant, or copyright-risky.
- Local-only fragments are insufficient because users expect account sync.

Existing evidence:

- Fake-door and business-model notes point V2.1 toward one-show activation and Pro limits on repeat AI generation.
- Prior implementation already proved StoreKit products, first-listen generation, and accountless local storage are feasible.
