# Assumptions

- A compact status entry is enough for users to understand the companion lifecycle without a new top-level module.
- A local “mark confirmed” action is understandable before account and deep-link infrastructure exists.
- An optional companion name provides useful identity without requiring Contacts permission.
- The idea is falsified if users expect real remote acceptance and treat local confirmation as untrustworthy or confusing.

The supplied interactive HTML prototype is the primary design evidence. The existing Current surface already keeps Companion visible across show phases.
