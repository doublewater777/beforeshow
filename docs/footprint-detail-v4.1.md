# 足迹详情 V4.1 功能规格

状态：已确认
确认日期：2026-08-09
视觉参考：`/Users/water/Downloads/myshows-and-footprint-detail-v4.1-share-composer.html`

## 目标

将从「足迹」进入的单场详情拆成独立的私人回看页面，并完成现场回忆卡片的选择、预览和系统分享闭环。足迹详情服务回顾；现场详情继续服务现场记录管理。

## 职责边界

- 「我的现场 → 现场详情」是查看和维护现场信息、当前展示、延期/取消状态以及删除整场记录的唯一入口。
- 「足迹 → 足迹详情」只回看已进入足迹的现场，不编辑现场资料、不修改现场状态、不删除整场记录。
- 足迹列表每一行直接进入足迹详情，移除原有「查看详情 / 编辑记录 / 删除记录」更多菜单。
- 足迹详情可以维护属于回忆的内容：编辑或删除已有记忆碎片，添加、替换或删除票根与时刻表。

## 页面结构

页面从上到下固定为：

1. 返回导航与「足迹详情」标题
2. 现场回忆头图：日期、城市、现场名称、场馆和档案身份
3. 记忆碎片
4. 留下的东西：票根、时刻表
5. 同行，仅在存在已确认同行关系时出现
6. 现场资料：时间、场馆、城市、艺人
7. 底部「分享这场回忆」主按钮，仅在存在至少一项分享素材时出现

页面沿用现有 Stage 设计令牌、间距、字体和可访问性尺寸，不从 HTML 硬编码颜色或字号。足迹详情出现期间继续隐藏根标签栏。

## 档案身份

所有身份均动态计算，不持久化序号。

### 第 N 场现场

- 只计算未取消且已经进入足迹的现场。
- 按有效开场日期和开场时间升序排列。
- 补录更早现场或修正日期后，所有受影响序号动态校正。
- 同一开场时刻使用创建时间和 ID 作为稳定排序兜底。

### 某城市第 N 场

- 城市文本只去除首尾空格，完全相同才视为同一城市。
- 不合并「杭州 / 杭州市」或「上海 / Shanghai」。
- 城市缺失时不显示此项，剩余身份重新均分。

### 与某同行者第 N 次见面

- 每场现场最多一位同行者。
- 只计算已确认、已结束、具备非空姓名的同行关系。
- 跨场只按去除首尾空格后完全相同的姓名归并。
- 姓名为空时不显示此项，也不跨场合并。
- 同行区块不显示「仅自己可见」或其他隐私标签。

日期眉题直接使用保存的城市原文；拉丁字母内容可转大写，不自动转拼音或英文。城市缺失时只显示日期。

## 记忆拼贴

- 读取当前现场的全部记忆碎片，按 `createdAt` 从早到晚排列，不按记忆阶段分组。
- 一条记忆碎片只占一个拼贴卡片。
- 多媒体碎片使用第一项媒体作为封面，并标明媒体数量；点击后进入整组媒体轮播。
- 视频卡片显示真实视频缩略图、播放标识和已保存的真实时长。
- 纯文字碎片显示文字摘要，不伪装成图片。
- 点击已有碎片后允许进入现有统一编辑器进行编辑或删除。
- 足迹详情不提供新增记忆入口。
- 没有碎片时仍保留「记忆碎片 · 0 条」及只读空状态「这一晚还没有留下记忆碎片」。

## 票根与时刻表

- 两种卡片始终显示；没有图片时显示添加状态。
- 复用现有 `ShowAssetSheet` 的选择、预览、替换和删除能力。
- 每场每种类型仍最多保存一张图片。
- 这些图片是否加入分享由分享编辑器单独决定，不因已保存而默认公开。

## 同行与现场资料

- 同行关系为 `.confirmed` 时展示同行区块，最多一位；其他状态隐藏整个区块。
- 同行区块展示头像占位、姓名和共同足迹次数，不提供管理动作。
- 资料区标题使用「现场资料」，不使用「演出资料」。
- 资料字段保持只读，并复用现有时间与缺失值格式化规则。

## 分享编辑器

### 可选素材

- 每张照片是一个独立分享素材。
- 每个视频使用视频封面作为一个独立分享素材。
- 一条多媒体记忆碎片会展开成多个可选分享素材，但不会改变原碎片关系。
- 已保存的票根和时刻表各自是一个可选分享素材。
- 纯文字碎片与媒体配文不是分享素材。

### 选择规则

- 卡片必须包含 1–3 项分享素材。
- 照片、视频封面、票根和时刻表共同占用三个名额。
- 尝试选择第 4 项时不改变当前选择，并提示「最多选择 3 个画面」。
- 全部取消选择时禁用「分享图片」，提示「至少选择一个画面」。
- 每次打开编辑器都重新生成默认选择；关闭或取消后不保存本次配置。
- 默认按记录时间从早到晚选择最多三张照片；照片不足时再按时间使用视频封面补齐。
- 票根和时刻表始终默认关闭。
- 不支持拖拽排序。成品先按记录时间排列记忆素材，再排列票根、时刻表。
- 开启票根时显示提示：分享前检查二维码、订单号及其他个人信息。

### 卡片固定内容

- 日期与城市原文
- 现场名称和场馆
- 最多两项档案身份：固定显示「第 N 场现场」；第二项优先显示「与姓名第 N 次见面」，没有具名同行者时显示「城市第 N 场」
- BeforeShow 品牌标识

已确认且有姓名的同行者可以进入分享卡片，并在预览中明确可见。精确座位、纯文字碎片和媒体配文不得进入预览或导出图片。

### 输出与分享

- 成品为 1080 × 1350、4:5 竖版 PNG。
- 预览与最终渲染使用同一内容组件，避免所见与所得不一致。
- 点击「分享图片」只向 iOS 系统分享面板传递 PNG，不附带默认文字，也不自动写入照片图库。
- 没有任何可用分享素材时，足迹详情不显示底部分享按钮。

## 实现约束

- 新增独立的足迹详情视图与纯计算快照，不继续让足迹入口复用 `ShowDetailView`。
- 统计、默认素材选择、选择上限和分享内容过滤应放在可单元测试的纯逻辑类型中。
- 复用现有记忆媒体查看/统一编辑器、`ShowAssetSheet`、Stage 设计系统和图片渲染能力；只把当前私有实现提升到必要的共享边界，不复制完整流程。
- 不新增兼容或迁移分支；应用尚未上线。

## 非目标

- 多人同行或稳定的跨场同行者 ID
- 城市别名、拼音或中英文归一化
- 从足迹详情新增记忆碎片
- 从足迹详情编辑现场资料、修改现场状态或删除整场记录
- 分享配置草稿、手动素材排序、分享文字
- 方形、9:16 或其他分享模板
- 公开主页、动态、评论或社交可见范围

## 验收标准

- 足迹列表普通行、搜索结果等所有回看路径进入独立足迹详情；我的现场仍进入现场详情。
- 足迹列表不再提供编辑或删除菜单。
- 总体、城市和同行序号在补录、改期、缺失城市、未命名同行和同名同行场景下符合上述规则。
- 拼贴正确处理纯文字、照片、视频、多媒体碎片、空状态以及编辑后刷新。
- 票根与时刻表的添加、替换、删除会立即反映到详情和分享素材列表。
- 分享选择始终保持 1–3 项限制，默认值、取消、重新打开和票根警告符合规则。
- 预览和导出的 PNG 内容一致，尺寸为 1080 × 1350，且没有精确座位、文字碎片或媒体配文。
- 系统分享仅收到 PNG。
- 新增和受影响单元测试通过，iOS 工程在 iPhone 17 模拟器目标上成功构建。
- 在 iPhone 17 模拟器保存至少以下本地截图：完整足迹详情、空记忆状态、分享编辑器、包含票根警告的分享编辑器、系统分享面板。截图存放于临时目录且不加入 Git。
