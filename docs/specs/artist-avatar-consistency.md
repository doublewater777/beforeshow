# 统一艺人头像：实现规格（Grill 16 项决策）

## 目标和边界
同一个**已确认 Apple Music Artist ID** 在当前、时刻表、现场模式、足迹、听、分享预览、Widget 和 Live Activity 的**艺人头像**应使用一致的最终图像来源。明确属于专辑、CD、歌曲、现场海报的图片不改变语义。艺人照片不可用时，不用歌曲封面伪装头像。

## 身份和匹配
- 保留现有严格、无歧义自动匹配或用户手动确认；搜索候选、相似姓名不构成关联。
- 按 Artist ID 而非规范化姓名索引已确认身份；不同 ID 不互相借图。
- 未关联的艺人可使用能确认身份的可信艺人照片，否则占位符；不自动绑定最相似结果。
- 手动重绑或解除关联立即清除旧身份的展示关联；不得在新头像下载期间显示旧身份照片。
- 同名历史场次不自动改写已确认的不同 ID。

## 来源优先级
1. 已确认 ID 对应的 Apple Music **艺人照片**，包括缓存中已验证来源的官方照片。
2. 在官方艺人照片确实不可用时，同一身份的可信其他来源艺人照片。
3. 占位符。

MusicKit Artist.artwork 可为空。iTunes 的歌曲 artworkUrl100 是歌曲/专辑图，**不能**作为艺人头像。旧记录只存 URL、缺乏来源证明；未知来源图片不得自动提升为可信头像。来源不明的旧图不跨场次传播。

## 统一解析架构
- 提供 App 范围内单一按 Artist ID 查询的头像解析入口，统一来源分类、选择、缓存、刷新、身份隔离；无 ID 时提供显式的未关联展示路径。
- 展示时由解析结果覆盖旧模型字段，而不是为每次官方图片更新批量改写所有 Show / TimetablePerformance。
- 保留 Show.artists.avatarURL、TimetablePerformance.artistAvatarURL 等既有持久化字段与序列化兼容性；不要求新的破坏性 SwiftData schema migration。
- 旧历史数据按需渐进解析；不阻塞启动，不做一次性全库联网扫描。
- 搜索和候选模型必须区分艺人头像与专辑封面、已验证来源与未知来源。不得把已有头像非空当作拒绝官方图升级的理由。

## 缓存、离线与更新
- 本地已缓存的官方照片优先；离线缺失时退到已缓存的可信其他艺人照片，再到占位符。
- 以 Artist ID 缓存头像解析状态；图片文件可复用现有 URL 级磁盘缓存，但 URL 相同不意味着永久有效。
- 按需后台重新验证，设置有限刷新频率与失败退避；网络失败不抹掉已验证官方图；避免加载闪烁和频繁请求。
- 异步响应提交前校验目标 Artist ID 和请求版本，防止切换现场、改绑、重入后旧响应覆盖新状态。
- 不为头像单独请求 MusicKit 授权；沿用无需额外权限的可用公开检索及现有授权状态。
- 不新增 iCloud 图片缓存同步；不同设备独立解析。同行分享仍可传递身份和可移植 URL，接收方必须通过同一来源规则解析。

## UI 接入
- 所有**艺人头像**展示路径统一使用解析结果：Show/Current、时刻表矩阵及演出检视抽屉、现场模式、足迹艺人肖像、「听」艺人入口、艺人头像分享导出、实时活动/Widget 中的艺人头像。
- 维持明确的专辑封面/唱片/海报用途；足迹大卡片若现有语义是专辑封面，不能仅凭组件名 Avatar 擅自替换其视觉含义，应按实际用途分类。
- TimetableArtistAvatarStore 当前按艺名缓存，不能继续作为已确认 ID 的最终权威。
- ListeningRoomCoordinator 当前仅在旧 avatarURL 为空时写入自动匹配图，必须允许官方头像提升优先级。
- FootprintArtistArtworkPolicy 当前 avatar ?? album 仅可用于确认为封面用途的界面，不能复用于头像。
- WidgetDataSync 当前从 TimetablePerformance.artistAvatarURL 构建快照，应在快照边界注入统一解析后的来源。更新头像时更新受影响的本地缓存/快照并请求 WidgetKit/ActivityKit 刷新；不保证 App 被系统挂起时立即刷新。

## 验收与测试
1. 同 Artist ID、不同现场、不同旧 URL，全部显示同一官方头像。
2. 相同姓名、不同 Artist ID，不混用图。
3. 旧图来源未知、歌曲图被误当头像，均不传播；缺官方图时按可信来源/占位符降级。
4. 无官方头像、未授权 MusicKit、离线、网络错误、图片 URL 不变但内容更新，均符合回退和刷新规则。
5. 手动更换 ID、解除关联、跨现场快速切换、异步结果乱序，不显示旧身份图。
6. 历史足迹和时刻表渐进升级，不破坏旧 SwiftData 数据；启动不批量阻塞。
7. 当前、时刻表、听、足迹、分享及 Live Activity/Widget 快照的图像来源一致；专辑封面仍独立。
8. 同行共享接收方不将未经验证的 URL 提升为官方照片；多设备无需同步图片字节。
9. 刷新频率、失败退避、磁盘缓存复用及实时活动更新有可控的测试接缝。

## 不在范围
不改变 Apple Music 匹配策略的严格程度；不引入用户上传头像编辑器；不改 CD 封面与唱片拼接规则；不建设云端头像图库；不主动索要音乐权限。
