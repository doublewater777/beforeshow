# Plan 05 · 去程计划 UX

> **Audience:** 执行型 agent · `Agents.md` · iPhone 17  
> **关联:** Plan 01 首页出行提醒依赖本模块「已保存出门方案」与打开地图。

---

## 0. 问题

1. 页信息架构重，首次用户不知三步是什么。  
2. 保存成功后闭环弱（首页提醒在 Plan 01）。  
3. 缺出发地/目的地时错误要可行动。  
4. 文案勿承诺「往返/实时导航」（返程 UI 未启用）。

---

## 1. 目标

### 1.1 首次引导（无已保存方案时）

页顶 `BSTipPromptCard` 或等价，固定三步：

1. 填出发地（可定位 / 常用出发地）  
2. 选一种交通方式看选项  
3. 保存为出门方案  

副文：`不替代地图导航，只帮你定出门时间。`

### 1.2 已保存方案态

- 顶部 **摘要卡**（出门时间、方式、时长、预计到达）始终可见。  
- 主 CTA：`打开地图`（与 Plan 01 共用逻辑）。  
- 次 CTA：`更换方案` / 重新推荐（沿用现有，勿删保存优先规则）。

### 1.3 交通选项

- 标签解释体验差异（更稳 / 少换乘 / 赶时间），**禁止**「最佳/最优」。  
- 排序：产品默认公交优先（若代码已是，保持；否则调到：公交 → 打车参考 → 驾车）。

### 1.4 错误与缺信息

| 情况 | 文案方向 |
|------|----------|
| 无出发地 | 请先填写或定位出发地 |
| 无目的地 | 补充场馆/地址（给入口编辑） |
| 地图失败 | 可手动保存出门方案，勿编造路线 |
| 无地图链接 | 已有 toast「暂无地图链接…」保留 |

### 1.5 保存规则（勿破坏）

- 用户保存内容优先于新草稿；禁止静默覆盖。  
- 每场最多一个已保存出门方案。  
- 出发地回写「常用出发地」逻辑保留。

### 1.6 与首页

- 保存成功后：toast「已保存出门方案」；若容易做，`dismiss` 回首页（可选）。  
- 保证 `hasSavedDeparturePlan == true` 后 Plan 01 能读到字段。

## 3. 步骤

1. 读 `RoundTripPlanView` 状态机：`hasSavedDeparturePlan`、推荐、手动、venue editor。  
2. 无方案：三步引导 UI。  
3. 有方案：摘要卡 + 打开地图。  
4. 错误文案可行动化。  
5. 抽 `openInMaps` 若 Plan 01 需要。  
6. 全文搜索「往返」「导航」用户可见文案，改为「去程」「地图」等。  
7. Build + 手测。

```bash
cd apps/ios && xcodebuild -scheme BeforeShow -destination 'platform=iOS Simulator,name=iPhone 17' build
```

## 5. 禁止

- 实时导航、拼车、多方案首页展示未保存选项  
- 重写整个推荐算法（UX 层）  
- 启用返程完整 UI（CONTEXT：第一版不启用）
