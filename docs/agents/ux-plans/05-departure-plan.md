# Plan 05 ·「怎么去」UX

> **Status:** 已实施
> **Target:** iPhone 17
> **Visual source:** `mrnv1rxl-beforeshow-home-feature-cards.html` 的 route 卡、时间轴与底部表单

## 1. 产品边界

- 整个模块叫「怎么去」；开场前只展示去程，开场后只展示返程，不提供方向切换。
- 返程从开场开始持续到当前现场被切换；已结束后不改成「下一场出行」。
- 每场分别保存一个结构化去程方案和一个结构化返程方案，互不覆盖。
- 删除旧自由文本、AI 往返草稿、兼容 predicate、常用出发地和通用手动方案。
- MapKit 是唯一地图事实来源；旧高德决策由 ADR-0021 取代。

## 2. 页面层级

- HTML 不是仅供参考的 moodboard，而是高保真视觉目标；除本文件明确确认的功能差异外，route 卡的色彩、表面层级、留白、字号层级、圆角、描边、摘要三列、时间轴比例、底部表单与浮现动效都应尽量 1:1 还原。
- SwiftUI 实现优先复用现有首页设计令牌与共用卡片组件；若现有组件无法达到 HTML 效果，再做最小共享扩展，不另造一套视觉语言。
- 完整摘要、交通方式与时间轴直接展示在首页功能卡，不保留独立 `RoundTripPlanView` 详情页。
- 空态「快速生成」、右上角调整入口和自定义编辑均使用参考稿样式的底部表单。
- 删除独立「出行小助手」卡；Tips 不负责滚动或跳转到首页「怎么去」卡。
- 首页排序：开场前第二；开场中最后且低干扰；已结束及散场后停留期第一（推荐语义仅由排序承担，无「此刻推荐」标记）。
- 卡片结构：卡头仅一行 = 小字分类名（tone 色，无圆点、无编号），填充态右侧出现无框工具按钮（调整入口）；无胶囊徽章、无标题行。空态为分类名 + 一行说明 + 单个 CTA；填充态直接展示内容，不显示说明行。首页不再有推荐 chips 区。
- 卡片区分度：卡面整层铺 5% tone 色 + 顶部 tone 渐变 + tone 描边，四类卡（金/蓝/紫/橙）的渐变与描边强度递增，避免连续浏览时糊成一片深灰；装饰性圆点一律取消，只有承载语义的点（时间轴节点、概率标记）保留。
- CTA 层级：主流程（推荐卡）为金色实心胶囊，次要流程为描边 Ghost 胶囊，避免多张卡的按钮互相抢视觉权重。
- 页面 UI 修改完成后必须使用 iPhone 17 模拟器截图保存。

### 设计系统迁移

- HTML 视觉令牌升级为 BeforeShow 全局 V3 设计系统，不再继续扩展 `BSColor.Home` 这类首页专用命名。
- `DesignSystem.swift` 按 primitive → semantic → component 三层整理颜色、字体、间距、圆角、动效与状态令牌。
- 本次将首页和「怎么去」迁移到 V3；其他页面保留后续逐模块迁移，不在本次改写。
- 共享组件至少覆盖 `FeatureCard`、`StageBottomSheet`、`IconModeSelector`、`MetricSummaryGrid`、`TravelTimeline` 和 `InlineStatus`；业务阶段、MapKit 与文案不得进入设计系统。

## 3. 去程表单

- 出发地是文本字段，默认读取「我的位置」。首次需要时请求定位权限；拒绝后不重复请求，字段置空并内联提示用户搜索。
- 「我的位置」在生成时保存坐标与可读地点快照，之后不随设备移动静默刷新。
- 用户输入至少两个字后，MapKit 位置列表实时更新；必须选择一项取得坐标，未选择的自由文本不能提交。
- 不跨现场记忆上一次出发地，不保留 `SavedOrigin`。
- 现场有确认地址或坐标时直接作为到达地；只有场馆名或城市时要求从 MapKit 地点列表确认；完全缺失时引导编辑现场。
- 有确定开场时间时，希望到达默认开场前一小时，并提供一小时、三十分钟、十五分钟快捷值；延期且日期待定时由用户填写完整日期与时间。
- 首次默认选中驾车，但提交前不生成、不保存。

## 4. 交通方式

固定顺序与 MapKit 映射：

1. 驾车 → `.automobile`
2. 步行 → `.walking`
3. 公共交通 → `.transit`
4. 骑行 → `.cycling`
5. 自定义 → BeforeShow 自有类型，不映射 `.any`

- 表单使用五个等宽图标按钮，不横向滚动；选中态为参考稿金色状态，完整名称放在摘要中，并提供 VoiceOver 标签。
- 图标方向：`car.fill`、`figure.walk`、`tram.fill`、`bicycle`、自定义编辑图标；实现时使用当前 SDK 可用的 SF Symbol。
- 首页卡片不内嵌方式切换，只在摘要中展示当前方式；调整方式走「调整」表单，提交生成成功后才替换方案，失败保留旧方案。
- 不单列打车；不使用 `.any` 表示自定义。

## 5. 自定义出行

- 仅用于 MapKit 无法表达的接驳车、包车等用户安排，是删除通用手动方案后的唯一例外。
- 必填出发时间、预计到达和安排说明；地点沿用当前方向的已确认起终点。
- 卡片沿用三项摘要，但时间轴只显示用户提供的出发点与目的地，安排说明置于两点之间，不补地图路线步骤。
- 点选自定义只进入编辑态；字段完整并提交后才替换当前方案，取消时保留旧方案。
- 自定义方案不显示「打开地图」。

## 6. 返程

- 开场后首页空态文案：分类名「怎么去」、说明「填好目的地和离开时间」、按钮「备好返程」。
- 返程出发点默认为场馆（或去程到达地），只读摘要展示，可点「更改」换成地点搜索。
- 有去程时，预填去程出发地为返程目的地，并预选去程交通方式；没有去程时目的地为空、默认驾车。
- 返程离开时间有默认值：未散场取散场后 15 分钟（散场时刻 = 显式结束时间 > 结束日期 > 类型时长估算），已散场取 15 分钟后；并提供「现在就走」「散场后 15 分钟」（未散场时）快捷值，用户可改。
- 返程目的地同样必须从 MapKit 地点列表选择，是唯一硬输入；不能把开场后的「我的位置」当作目的地。
- 返程生成后自动保存，但不覆盖去程。

## 7. 时间轴与地图

- 视觉、摘要和阶梯式浮现按参考稿实现，并尊重 Reduce Motion。
- 摘要三列回答用户真正的问题：预计用时、出行方式、去程为「建议出发」（leaveAt）、返程为「预计到达」（arriveAt）。
- 时间轴只展示有信息量的节点：驾车/步行/骑行或无真实步骤的公交折叠为「出发 → 抵达」两行；公交拿到真实换乘步骤时中间节点为真实步骤（最多 4 个），不展示占位节点或写死模板路线。
- 同日显示 `HH:mm`；次日显示「次日 HH:mm」；超过一天显示具体日期与时间。
- MapKit 方案保留轻量「打开地图」，使用已保存起点、终点和交通方式接力 Apple 地图。
- 方案不自动刷新，展示最后更新时间；只有用户主动生成或切换成功后才替换。
- MapKit 失败时无旧方案则显示重试，有旧方案则继续展示旧方案。

## 8. 现场变化

- 现场延期且日期待定时仍可生成，用户自行填写完整希望到达日期与时间。
- 日期、时间、场馆或场馆地址变化后，原去程与返程保留但标为「待重新生成方案」，不再作为有效时间轴展示。
- 现场取消后禁止新生成，不展开旧时间轴，显示「这场已取消，无需安排出行」。

## 9. 验收

1. 首页空态、生成态、失败态、自定义态和待重新生成态均符合上述规则，并与 HTML route 区域进行逐屏视觉对照。
2. 开场前只显示去程；开场后只显示返程；每场两份方案互不覆盖。
3. 五种交通方式在表单中选择，提交生成后自动保存，失败保留旧方案行为正确；首页卡片不直接切换方式。
4. 所有地图节点来自 MapKit；自定义只显示用户输入事实。
5. 定位拒绝、模糊地点、缺场馆、延期、取消和跨午夜均有明确状态。
6. 删除独立详情页、出行小助手、旧草稿、常用出发地与通用手动方案后，无遗留调用。
7. 相关单元测试、iPhone 17 构建通过，并保存空态、去程时间轴、返程时间轴和自定义方案截图；截图需用于检查间距、字体、颜色、圆角、时间轴对齐和 sheet 层级，而不只是证明页面能打开。
