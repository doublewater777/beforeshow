# Plan 08 · 添加现场 UX（主转化）

> **Audience:** 执行型 agent · `Agents.md` · iPhone 17

---

## 0. 问题

添加现场是核心动作。常见摩擦：

1. 多步 sheet 返回路径晕。  
2. 链接/OCR 失败原因不够可行动。  
3. 成功后未明确「进入状态」下一步。  
4. 开场时间对通知很重要，表单强调不足。

---

## 1. 目标

### 1.1 入口页（`AddShowEntryView`）

保持三种方式卡片。检查：

- 副文准确：链接 = 大麦/秀动；OCR = 设备端不上传。  
- 取消按钮可达。  
- 垂直节奏：标题与卡片间距不要过大导致首屏只看到一种方式（可略减 `padding.top: 68` 若卡片被顶出屏）。

### 1.2 链接解析

- 不支持链接：`这个链接暂不支持。可以继续在下方手动填写。`（已有则统一）  
- 支持列表明示大麦、秀动。  
- 成功 → **可编辑确认页**（禁止静默直接 save 不确认）。  
- 失败保留草稿字段，不丢用户已填。

### 1.3 截图 OCR

- 仅设备端；隐私句保留。  
- 识别中：明确 loading。  
- 失败 → 手动编辑，预填已识别字段。  
- 不展示订单号等敏感（解析层应已滤；UI 勿新增敏感字段）。

### 1.4 手动 / 确认编辑（`ShowDraftEditorView`）

**必填强调：**

- 名称、开场日期、**开场时间**（通知依赖）。  
- 开场时间旁 hint：`用于开场前提醒；可先填大概时间。`  

可选字段：城市、场馆、艺人、座位等不挡保存。

### 1.5 保存成功后

顺序：

1. save SwiftData + 当前现场选择（现有逻辑保留）。  
2. 通知权限：添加后再请求（现有则保留）。  
3. dismiss 流程，回到首页。  
4. **成功反馈：** toast 或一次性：`已放入当前现场`。  
5. 不自动弹 Pro。

### 1.6 导航

- 入口 → 方式 → 编辑：返回键回到上一级，不是直接关整个 coordinator（除非只有一层）。  
- `AddShowCoordinatorSheet` 状态机读懂再改，避免 break。

## 3. 步骤

1. 画出现有 sheet 状态（entry/link/screenshot/manual/editor）。  
2. 收紧入口垂直空白。  
3. 统一失败文案 + 确认页必达。  
4. 编辑页时间 hint。  
5. 成功 toast。  
6. Build + 手测三种路径各一次（链接可用假失败）。

```bash
cd apps/ios && xcodebuild -scheme BeforeShow -destination 'platform=iOS Simulator,name=iPhone 17' build
```
