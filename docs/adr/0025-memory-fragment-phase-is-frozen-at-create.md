# Memory fragment phase is frozen at create time

## Status

Accepted — 2026-08-04

## Context

记忆碎片时间流按「开场前 / 进行中 / 散场后」分组。阶段可以在每次展示时按 `createdAt` 动态重算，也可以在创建时写入后固化。

动态重算会在用户修改现场开场或结束时间后让旧记忆换组，阅读不稳定。用户也不应手选阶段或记录时间。

## Decision

创建记忆碎片时，用其 `createdAt` 对照该现场当时的开场/结束边界，写入 `记忆阶段` 并固化：

- 开场前：`createdAt < 开场时刻`
- 进行中：`开场时刻 ≤ createdAt < 结束边界`
- 散场后：`createdAt ≥ 结束边界`
- 取消或延期待定等无可靠边界：兜底为进行中
- 多日现场按该记忆所属日的开场/结束钟点判定；当日结束后、次日开场前的记忆属散场后
- 用户手动结束现场后，新建记忆自然落入散场后；已有记忆不重算
- 编辑记忆只改内容与媒体，不改 `createdAt` 与阶段
- 历史数据迁移一次：按现有 `createdAt` 与当前现场时间写入阶段，之后不再重算

时间流组序固定为散场后 → 进行中 → 开场前；组内按 `createdAt` 最新在上。

## Consequences

- 需要在 `MemoryFragment` 上持久化阶段字段
- 修改现场时间不会重排历史记忆；若用户在错误时间补记，阶段反映的是补记时刻而非媒体拍摄时刻
- 阶段解析逻辑必须与现场时间边界（含默认结束时长、多日每日循环、`endedAt`）共用同一套输入
