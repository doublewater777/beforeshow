# Recommend unused features through notifications and the countdown card

2026-10-01 产品决定：通知和倒计时信息卡主操作的第一目的，是把用户带进这场现场此刻用得上、还没用过的功能。覆盖优先于克制和条数上限；约束是不让用户难受。节点表与主操作表见 `PRODUCT_DEFINITION_V2.1.md` §07。

## 功能推荐

- 用于添加后次日、T-14、T-7、T-3 四个推荐节点，以及倒计时信息卡的推荐主操作；只围绕当前现场。
- 候选按表中顺序，取这场还没用过、没被跳过、前提条件满足的第一个（没登录 iCloud 不推同行）；在其他现场用过的功能排到最后。没有候选时，推荐节点不发，主卡主操作留空。
- 「用过」的判断：小组件看是否已添加任一「开场前」小组件；同行看这场是否已有同行或已发出邀请；听看这场是否听过任意一首；时刻表看这场是否已有时刻表图片；散场仪式看是否已完成；记忆碎片看这场是否已有记忆；足迹看是否打开过这场的足迹详情；添加现场看是否已有未来现场。
- 一个功能在主卡上最多露出 2 个自然日（首页实际可见才算），推荐通知送达也算一次露出。没点就本场跳过；点过即算处理过。
- 同一功能连续两场被跳过，以后不再推荐，直到用户自己用一次。
- 主卡一天最多换一次，只在当天第一次进入首页时换；用户完成后当场收起，次日再给下一个。当天有推荐通知时，主卡推同一个功能。
- 当天开场前的路线、现场中的记一段记忆、未确认散场时的确认已结束是固定主操作，不参与轮换。
- 不推荐票根、动态封面和 Pro（App Store 审核指南 4.5.4）；散场次日不推记忆碎片。

## 通知

- 文案先说这场现场（名称、还有几天、开场时刻、场馆），功能只作为此刻可以顺手做的事；不写「试试」「新功能」「你还没」。说「去见」时用艺人名，多艺人或没有艺人时用现场名。散场后的文案不预设好坏。
- 点通知打开通知里那一场的对应功能，不改变当前现场。听只服务当前现场，非当前现场的听歌通知打开该场详情。
- 落地页先给内容和按钮，用户点了才弹系统授权；用户正在编辑时，等编辑结束再跳转，不冲掉内容。
- 用户用了某个功能后立即重排，并撤掉通知中心里推荐它的通知；从通知中心点开旧通知时，看到的是已完成状态。
- 任何一场进行中时，其他现场的推荐节点跳过，T-1 顺延到这一场预计散场后。
- 不加红点，不用 App 角标；通知权限被拒时，不在主卡催开通知。

## 实时活动

开场前提供「路线」，开场后提供「记一段记忆」。

## Considered Options

- 保持情绪曲线，期待期四条都邀请听歌。否决：只覆盖听和记忆，同行、时刻表、路线、散场仪式、足迹没有主动入口。
- 按固定顺序轮播全部功能，不看是否用过。否决：反复推已经用过或明确不用的功能，像广告。
- 主卡加「不再提示」。否决：多一个输入；露出天数足以判断。
