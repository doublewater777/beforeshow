# Current Show listening reminders

Issue #364. 修订 ADR 0037 的通知推荐；倒计时信息卡候选顺序保持不变。

## 决定

- 「听」从通知功能推荐候选中移除；T-7 只推荐同行，T-3 只为音乐节推荐时刻表。
- 当前现场从添加当日起排听歌提醒：T-31 以前周六 20:00；T-30 至 T-15 每三天；T-14 至 T-2 每晚。以演出时区的自然日计算，跨夏令时保持 20:00。
- 单艺人顺序为大合唱、最新专辑、精选歌单、新歌、深挖、其余专辑。多艺人按想看、演出时间、阵容顺序轮换，每两位插一张主题合辑；一轮后再推后续唱片。单曲不参与。
- 过去的节点占用队列；未来节点跳过已完整听过的唱片。真实收听证据决定听完，手动标熟悉不算。
- 当天已有功能推荐或已收听时不排。长期未收听时，从最近一次收听后的第四个预排节点起，按距开场天数能被三整除降频，周更不变；新收听后恢复。无缓存最多每三天，队列用完隔天重听大合唱。
- T-1 合并进「明天开场」：单艺人大合唱，多艺人优先想看节目。当天合并进开场前三小时：优先节目，兜底大合唱；正文仍打开路线。临近开场补发不带听歌追加句及播放动作。
- 听歌与前一天提醒用完整现场名作标题，正文不重复现场名。日常提醒按大合唱、专辑、精选、新歌、深挖及循环大合唱区分文案，不叠倒计时；前一天只说「明天开场／开始」，不报具体时刻，按大合唱或想看节目区分正文。专辑正文带艺人名。
- 正文打开唱片详情；「播放」前台动作直接装入播放，按 ADR 0040 选择完整或试听。通知入口不请求系统音乐授权。失效唱片退到艺人范围或听首页。
- 只从本地缓存读阵容，不后台请求曲库。节目与主题合辑复用听房间的组装，保持唱片 ID 一致。

## 设置与兼容

当前版本只有「开场提醒」系统通知权限入口，没有独立「准备」开关。按用户确认沿用该权限，不增加设置或 UserDefaults key。

不改 SwiftData 模型。新 milestone raw value 为 `listeningReminder`，请求标识包含现场、节点与触发时刻。既有节点、深链 URL 和 widget kind 不变。通知 userInfo 增加可选唱片及艺人字段；旧载荷仍可解析。未知节点在旧版本上沿用兜底，没有 showStartTime，因此不成为开场提醒完成标记。升级重排撤销过期待发请求，待发总上限仍为 56，按通知类别优先分配，每类按触发时间取前。

## 未发送分支清理

删除已不可达的开场记忆通知、普通现场晨间路线通知、散场第三天未确认兜底及旧通知推荐文案；移除添加后次日与前十四天的非持久化推荐槽位。旧 milestone raw value `addedFollowUp`、`fourteenDaysBefore`、`openingMemory` 只用于正确解码历史排程记录，不再关联推荐槽位或生成新通知。SwiftData 字段、既有深链和共享首页推荐不变。

## 可靠性复核（2026-10-22）

- 56 条额度依次保留所有现场的开场提醒、当前现场的想看演出提醒、其他生命周期提醒，最后才安排听歌。每类按触发时间；重要提醒本身超额时仍只取该类最早的节点。数据库保留记录不代表系统已登记。
- T-1 与开场当天只选现场开场日期对应的想看合辑；当天没有想看节目则用大合唱，不借用第二、三天合辑。整场开始后不新增普通准备期听歌提醒。
- 「每天一条」只约束准备期的非紧急推荐，不限制当天时刻表和想看艺人的时效提醒。
- 降频是按预排节点模拟的长期未收听规则，不宣称识别真实的三次忽略。功能推荐占用日不计数；不增加送达日志。
- 阵容变化重排时，优先用通知中心仍可读到的已送达唱片载荷还原对应日期的目标，未来队列跳过这些唱片。新增艺人不再被这些历史节点错误消耗，排除艺人也不会导致立即重复已有载荷里的唱片。用户清除通知后无法还原的日期仍按理论节点计算，不承诺完整历史去重，不新增持久化格式。
