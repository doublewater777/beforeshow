# 歌单猜想 UI matches the home feature-cards HTML prototype 1:1

App UI for 歌单猜想 targets the current home feature-cards HTML prototype at three surfaces: **home setlist card** (empty CTA, five-row preview, open-all, filled-state edit/share tools), **setlist sheet** (generate status, four-tier rows with short hints, heart 最想看, footer actions, in-sheet edit mode with up/down/delete and add form, festival lineup), and **share sheet** (poster preview, save image, copy text). In-sheet edit is the default edit path; a separate full-page or secondary edit list is not the target. Card and title copy stay colloquial; a single bottom-of-sheet disclaimer may mention model-based guessing once, without “大模型” on every surface.

Pixel-perfect identity is not required under Dynamic Type and safe areas; structural and interaction parity with the prototype is. Prior sheet chrome that diverges (star-only rows, secondary edit sheet as primary, share-without-preview) should be replaced rather than kept as a second style. Domain rules from ADRs 0014–0018 and **0020** (no music-platform handoff, 歌单猜想 naming, four tiers + short hints with client enrich when generation omits them, heart 最想看) still apply.
