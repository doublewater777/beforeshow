# Opening hour owns live capture, not ending the show

现场中的首页主操作原先是「结束现场」。人已经在场时，这是错的主职。BeforeShow 把现场中的第一个小时定为开场记忆窗：主按钮改成「记一段记忆」，打开新增记忆（相机 / 图库 / 文字）；结束现场降到快捷区。过了这一小时，主按钮回到结束现场。窗口从开场时刻起算，一场一次，多日现场也只用这场的开场时刻；现场先结束，窗口一起结束。

开场时刻另发一条安静的开场记忆通知，点进去同样打开新增记忆。它和散场次日回看同属落到记忆的触点，不算第七条提醒。通知邀请留下一条记忆碎片，不是只叫拍照。添加现场时开场时刻已过但仍在窗内，则延迟补发一次；窗外不补。

## Considered Options

- 整段现场中都把主按钮换成记记忆。否决：结束现场仍要可发现，也不新造「短窗口」之外的整场主职。
- 窗口按第一次打开 App 起算。否决：与记忆阶段、通知预排共用的开场时刻对不齐。
- 音乐节每天一个窗口。否决：音乐节是一个现场；每天推一次会拆掉通知节奏。
- 已经开场一律不补通知。否决：到场才添加的人正是最可能留下此刻的人。
- 把开场记忆通知做成 time-sensitive，或写成只叫拍照。否决：不打断现场，也不把记忆碎片收成相机。
